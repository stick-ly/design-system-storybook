Evidence-backed constraints

  • Independent child repositories cannot depend on sibling source paths. The final canonical source repository is private stick-ly/design-system. Publish tested versioned packages to GitHub Packages; both consumers pin the same released version through their lockfiles. They use the owner-scoped @stick-ly/design-system directly for predictable dependency updates. The current local tarball is a temporary migration bootstrap, not the final distribution method.
  • Actual webapp and extension appearances differ: 114 token declarations match; 45 webapp and 24 extension declarations differ or are app-specific. Store shared declarations once and preserve composition-only values as explicit profiles. Base control visuals use the approved webapp design.
  • Current webapp source contains ambient shadows despite documentation prohibiting them. Extension bubble source contains WebKit-safe border/caret geometry despite older filter-only guidance. Refactoring must preserve current measured source, with design cleanup tracked separately.
  • Angular controls are CVAs with nullable value, focus, validation and keyboard APIs. Buttons also own routing, analytics and localized loading projection. Those application concerns stay in adapters.
  • Never retire a legacy implementation on compile or source-contract evidence alone.

Comparison and testing contract

  1. Use real old Angular components in Angular Storybook and frozen old Lit primitives in a comparison fixture. The shared Storybook catalogs new controls and paired comparisons; the original Lit renderer is temporary and must be retired after its replacement gates pass. Historical source references and original images preserve reviewability afterward.
  2. State manifest maps each component's old source, new tag, variants and behavior cases. Include default, hover, focus, active, disabled, loading, error, empty, selected and indeterminate where applicable; themes, sizes, long copy, icons, reduced motion, desktop 1280×720 and mobile 390×844.

Match shared button visuals against webapp originals; retain old-extension/new-shared comparisons as intentional design changes. Compare component crops and composition screenshots. Preserve before/after/diff files in ignored artifact directories. Missing state or baseline fails the gate; no automatic baseline updates.
  4. Behavior tests assert property/attribute synchronization, native keyboard activation, exact event count/detail, focus retention, form participation, Angular CVA and router semantics, reset, cleanup and hostile host-page styles.
  5. Run live Storybook while iterating. At final handoff run webapp pnpm test:visual:affected -- --base <review-base>, which remains broad in shadow mode, plus shared-package comparisons and real extension playground flows.
  6. Run consumer production builds at handoff; webapp SSR/hydration and extension package verification are separate proofs. Check Safari through existing web-artifact tooling and browser engines; physical-device claims require device evidence.
